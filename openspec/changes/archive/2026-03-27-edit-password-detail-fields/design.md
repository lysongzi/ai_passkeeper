## Context

当前应用有两个 UI 问题需要解决：

1. **详情页无法编辑**：`PasswordDetailView` 仅展示密码信息，目前没有编辑入口，用户需要从列表页重新打开添加页面才能修改内容
2. **分类选择器宽度不一致**：`AddEditPasswordView` 中分类选择器使用了 `.frame(maxWidth: .infinity, alignment: .leading)`，但实际宽度与上方输入区域不一致
3. **UI 优化需求**：编辑功能的 UI 需要符合现有设计规范

## Goals / Non-Goals

**Goals:**
- 在详情页添加内联编辑功能，支持直接修改标题、用户名、密码、备注、分类
- 修复分类选择器宽度，使其与上方输入区域保持一致
- 修复 UI 问题：编辑按钮多语言、密码宽度、分类显示、输入区域间距、删除按钮隐藏
- 保持代码简洁，不引入新的架构模式

**Non-Goals:**
- 不修改密码加密/解密逻辑
- 不添加新的数据模型字段
- 不引入第三方 UI 组件

## Decisions

### 方案 1: 详情页内联编辑
**决策**: 在 `PasswordDetailView` 中添加编辑模式

**理由**:
- 用户体验最佳：无需跳转页面即可完成编辑
- 实现简单：直接在详情页切换编辑/查看状态
- 分类也需要支持编辑（与添加页面一致）

**备选方案**:
- 跳转到 `AddEditPasswordView` 进行编辑（不使用，用户明确要求内联编辑）
- 弹窗编辑（需要额外的弹窗组件）

### 方案 2: 分类选择器宽度
**决策**: 使用 `.pickerStyle(.menu)` 修复宽度问题

**理由**:
- SwiftUI Picker 在 `.form` 中的默认行为导致宽度不一致
- 使用 menu 样式可以获得更好的宽度控制

### 方案 3: UI 修复
**决策**: 逐一修复 UI 问题

- 编辑按钮：添加多语言支持 `detail.edit`
- 密码显示：使用 `frame(maxWidth: .infinity)` 撑满宽度
- 分类显示：非编辑态也显示分类信息
- 输入间距：添加 `padding(.vertical, 8)` 优化垂直间距
- 删除按钮：编辑模式下隐藏

## Risks / Trade-offs

- **风险**: 编辑保存后需要刷新列表页数据 → 通过 `onSave` 回调通知父视图刷新
- **风险**: 详情页编辑时密码安全 → 保持与添加页相同的密码可见性控制
