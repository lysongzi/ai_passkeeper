## Context

需要对现有密码管家应用进行 UI 升级，基于 RedesignUI 原型工程的设计风格。原型使用 shadcn/ui 设计系统，采用深色/浅色主题支持。

**现有系统状态：**
- 使用 SwiftUI 开发
- MVVM 架构
- 已实现密码管理核心功能
- 支持中英文多语言
- 已有内联编辑功能

**设计约束：**
- 保持现有业务逻辑不变
- 支持 macOS 平台
- 保持深色/浅色主题切换
- 不引入新的外部依赖（使用 SwiftUI 原生组件）

## Goals / Non-Goals

**Goals:**
- 基于 RedesignUI 原型重塑整体 UI 风格
- 优化用户交互体验
- 统一各页面的视觉设计语言
- 修复之前 UI 实现中发现的 bug

**Non-Goals:**
- 不修改底层业务逻辑
- 不添加新的数据模型字段
- 不引入第三方 UI 库

## Decisions

### 1. 颜色系统
**决策**: 使用原型中的 CSS 变量定义颜色体系，转换为 SwiftUI Color 扩展

**理由**: 原型使用 oklch 颜色空间，SwiftUI 可通过自定义 Color 扩展实现类似效果

### 2. 组件样式
**决策**: 使用 SwiftUI 原生组件 + 自定义修饰器实现 shadcn/ui 风格

**理由**:
- 不引入第三方依赖
- 保持 SwiftUI 的声明式特性
- 便于维护和更新

### 3. 布局结构
**决策**: 保持现有 NavigationSplitView 结构，优化各区域样式

**理由**:
- macOS 原生导航模式用户体验好
- 减少重构风险

### 4. 输入框高度
**决策**: 统一输入框高度为 44-48pt（原型中 py-3 ≈ 48pt）

**理由**:
- 之前实现中输入框高度问题较多
- 需与原型保持一致

### 5. 圆角半径
**决策**: 使用 8-16pt 圆角（原型中 radius: 0.625rem ≈ 10px）

**理由**: 符合现代 macOS 应用设计趋势

### 6. 文案优化
**决策**: 对比原型和现有文案，选取更友好的表达

**示例**:
- "主密码" → "解锁"
- 分类选择更清晰的标签

## Risks / Trade-offs

- **风险**: SwiftUI 原生组件与原型效果可能存在差异 → 需手动调优
- **风险**: 主题切换实现复杂度 → 使用 Color Scheme 绑定
- **风险**: 大面积 UI 修改可能引入回归 → 保留现有 ViewModel 逻辑

## Migration Plan

1. 按模块逐步重构：解锁页 → 侧边栏 → 详情页 → 弹窗 → 设置页
2. 每完成一个模块进行构建验证
3. 最后整体测试和微调
